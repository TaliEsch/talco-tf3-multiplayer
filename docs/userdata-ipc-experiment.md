# No-op userdata IPC experiment

This is the next proposed experiment, not a recorded pass and not yet included
in the Safe Mode source mod. It uses only documented TF3 userdata and GUI APIs;
it does not inject code, patch files, send gameplay commands, or expose a
network socket from the game.

## Evidence and intended flow

`api\tealdef\app.d.tl:137-157` declares `loadUserdata`, `saveUserdata`, and
`getAllUserdata`; `:205-206` declares the userdata root. Installed first-party
GUI scripts use these calls. `api\tealdef\api\cmd.d.tl:780` exposes a scripting
event command for a later GUI-to-game handoff. Vehicle entity-window extension
parameters expose the selected vehicle entity and ownership state.

```text
TF3 GUI plugin --saveUserdata(outbox nonce/counter)--> per-user tf3mp directory
       ^                                                       |
       |                                                       v
 display response <--loadUserdata(inbox)------------ local helper poller
```

## Probe constraints

- Directory: a dedicated `tf3mp_status_1` folder below TF3 userdata, never the
  installation or save directory.
- Payload: schema version, random public nonce, monotonic counter, timestamp and
  literal probe status only; no secret, save content, player name or IP address.
- Maximum file size: 4 KiB; maximum one pending request and response.
- The helper must parse an allowlisted data grammar and must never execute or
  dynamically import the Lua file generated by TF3.
- Helper responses must be written to a temporary file in the same directory,
  flushed, then atomically renamed. Values must be serialized from strict
  integer/boolean/identifier allowlists, never concatenated untrusted Lua.
- Duplicate, stale, malformed, oversized or unexpected files are ignored with a
  redacted local diagnostic. They never reach game-script state.
- Kill switch: with the helper stopped or bridge disabled, the panel remains in
  Safe Mode and no action is submitted.

## Manual pass criteria

1. The already-reviewed Safe Mode panel and clocks load without errors.
2. Enabling the probe writes only the dedicated outbound userdata file.
3. The helper observes each counter once and writes one matching nonce response.
4. The panel displays the response within two seconds without freezing or
   altering simulation state.
5. Partial, oversized, malformed, stale and duplicate fixtures are rejected.
6. Pausing, saving/reloading, stopping the helper and disabling the mod leave
   normal single-player behavior intact and create no gameplay command.
7. Logs contain schema/counter/result metadata but no secret or raw file body.

Any Teal error, unsafe path behavior, non-atomic read, unbounded polling cost,
unexpected simulation mutation or inability to distinguish stale data is a
failure. Preserve the log and stop before implementing vehicle control.
